Daily Technical Snippet

Late chunking — embed the whole document first, then cut the chunks

Chop a document into chunks, embed each one alone, and every chunk forgets the document it came from — “it”, “the company”, “that figure” all point at nothing. Late chunking flips the order: run the whole document through a long-context embedding model first to get token-level embeddings, then pool those tokens into per-chunk vectors. Each chunk still retrieves individually, but its vector was computed with the full surrounding context in view — so references resolve and the fragment carries the meaning of the section it lived in, at no extra storage over ordinary chunking.

Learn more

It costs almost nothing at query time — still one vector per chunk — but it needs an embedding model with a genuinely long context window and mean-pooling over token spans rather than a single [CLS] vector. It stacks cleanly with reranking and with parent-document retrieval: late chunking fixes within-document context, small-to-big fixes return context. For Kepler the lesson is the one the product is built on — a memory is only as good as the context it was encoded with; capture the surrounding thread when you write a fact, and recall stops handing back orphaned snippets a user can't verify.
