Daily Technical Snippet

Learned sparse retrieval (SPLADE) — dense recall with keyword-level receipts

Dense vectors are great at meaning but blind to exact terms: ask for invoice #4471 or the error code ETIMEDOUT and semantic search happily returns something about billing that misses the literal string. Classic keyword search (BM25) nails the token but not the meaning. SPLADE splits the difference: a transformer predicts a sparse, term-weighted vector over the whole vocabulary — expanding a document with related words it doesn't literally contain, while still keying on the actual terms. You get dense-like recall in a representation that's interpretable and exact-match-friendly, and it runs on the same inverted indexes BM25 already uses.

Learn more

SPLADE is why "hybrid search" (today's Oracle memory upgrade leans on exactly this) works so well: learned sparse handles identifiers and rare terms, dense handles paraphrase, and you fuse the two. Because each dimension is a vocabulary term with a weight, you can read off why a passage matched — no opaque 1,024-float blob. For Kepler that transparency is the point: a memory a user owns should be able to show its reasoning for a retrieval, not just assert a similarity score — auditable recall, not a black box.

→ SPLADE: Sparse Lexical and Expansion Model for First-Stage Ranking (Formal et al., 2021)
