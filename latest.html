Daily Technical Snippet

Semantic chunking — splitting documents by meaning, not character count

Most retrieval pipelines still slice documents into fixed ~500-token blocks, which happily cuts a single idea in half at an arbitrary boundary — so the retriever fetches half an argument and the model answers from a fragment. Semantic chunking embeds sentence by sentence and starts a new chunk only where the meaning actually shifts — a large cosine-distance jump between consecutive sentences — so each chunk is one coherent thought. Cleaner chunks in means cleaner retrieval out: fewer half-ideas, less noise in the context window, better-grounded answers.

Learn more

The cost is compute: you embed every sentence up front and scan for breakpoints, versus splitting on a character count for free. In practice teams use a hybrid — semantic boundaries with a hard max_chunk_size cap so a rambling section can't become one giant block — and pair it with a small overlap so context isn't lost at the seams. For Kepler the principle is the point: a memory a user owns should be stored as meaningful units a person could actually read back, not arbitrary 500-character shards — coherent chunks are what make "recall and show your working" possible rather than a pile of fragments.

Top Story · AI & Agents

MCP goes stateless: the 2026-07-28 spec ships — the agent protocol Kepler rides just became web-scale infrastructure

On 28 July the Model Context Protocol shipped its biggest revision since remote MCP launched, and the headline is a stateless protocol core: the initialize handshake and Mcp-Session-Id are retired, so every request is self-describing and any request can hit any server instance behind a plain round-robin load balancer — no sticky sessions, no shared session store. It also brings cacheable tool/list results, header-based routing (Mcp-Method/Mcp-Name), Multi Round-Trip Requests for mid-call elicitation, OAuth hardening, and a formal extensions framework (Tasks, MCP Apps, Enterprise-Managed Auth). All four Tier-1 SDKs ship same-day; TypeScript and Python have each crossed 1B downloads. AWS, Google Cloud, Microsoft Foundry and Cloudflare are on it day-zero.

This is Kepler's delivery rail maturing into production plumbing, and it lands squarely on your roadmap. The half you should own loudest is authorization: issuer-bound credentials, RFC-9207 validation and Enterprise-Managed Auth are exactly the primitives a "user-owned, access-controlled memory" pitch needs — the spec just standardised your security story for you. The move: be spec-current on 2026-07-28 and enterprise-auth-ready before rivals finish migrating, and say it plainly — "Kepler is a stateless, portable MCP memory server that speaks the new auth model." When the substrate re-platforms, the tools that are ready first get adopted.
